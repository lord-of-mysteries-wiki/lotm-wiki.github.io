# 词条链接建议

运行 `node tools/suggest-wiki-links.js`，生成 `docs/wiki-link-suggestions.tsv`；也可在命令后指定输出路径。清单是 UTF-8 TSV，可用电子表格打开。`docs/` 在本项目中被 Git 忽略，清单是本地扫描结果，重新运行会覆盖该文件。

扫描所有 Markdown 页面正文，以人物、物品、世界观下的途径、组织和国家页面标题作为候选名称。同一来源页中指向相同候选目标的名称合并一行，显示首次出现的原文件行号、摘录、出现次数及所有同名候选目标。同名目标标为“同名歧义”，其余标为“待核对”。时间线简记只发布摘要、不发布 Markdown 正文，正文中的匹配通常标为“简记正文未发布”，不能仅修改正文来增加读者可见的链接；如果候选目标已通过摘要链接数据关联，则标为“简记摘要已有目标”。该状态只说明目标已链接，不代表正文匹配本身已消歧。摘要中的候选另标为“简记摘要待核对”或“简记摘要同名歧义”，核实后可通过事件数据 `event_summary_links` 配置链接；时间线和故事日历共用这些数据。

清单仅供人工审核：标题可能是普通词语、其他人物或作品名称的一部分；匹配不证明人物关系或事实。核对上下文和目标后，再按生成页面的实际相对路径添加链接。工具不会修改词条，也不会自动应用候选。它跳过常见的行内链接、代码和注释，但并非完整的 Markdown 语义分析；引用式链接、多行 HTML、复杂表格等可能产生误报或遗漏。名称紧接“途径”时，若存在同名途径介绍，优先建议该介绍页；仍须人工检查指代。工具会跳过在同一页面中已用相对 Markdown 链接指向的目标；绝对地址、HTML 链接及其他复杂写法可能无法识别。

时间线摘要还会借用已有摘要链接的文字发现别名，并标为“简记摘要别名待核对”。只有所有已有用例都指向同一个现存页面的名称会进入这一类；即使如此，也可能碰到普通词语或不同身份，需要结合语境判断，不能自动应用。此功能不推断人物关系，也不扫描正文别名。

人物、物品和世界观词条会自动列出指向该词条的已发布时间线摘要。反向列表只使用摘要中实际出现、且已通过 `event_summary_links` 明确关联的文字；列表链接到时间线事件锚点，未发布正文中的候选不会自动加入。

如果事件正文中出现了带间隔号的人物全名，而摘要中出现其一部分，或者正文名称带引号而摘要省略了引号，扫描器也会提出“简记摘要简称待核对”。例如正文写“海纳斯·凡森特”、摘要写“海纳斯”时可以提出建议；同名或相似名称仍须结合事件内容判断。

已审核的误匹配可记录在 `tools/wiki-link-rejections.json`；记录包含来源、名称、目标、原文摘要与理由。排除适用于正文和时间线简记摘要，仅在原文行及候选目标均未变化时生效；正文、摘要或目标发生变化时会重新进入清单。其他未审核的出现位置仍会显示。

## 自动添加明确链接

运行 `node tools/auto-link-sequences.js` 预览，使用 `node tools/auto-link-sequences.js --apply` 将链接写入来源文件。脚本仅处理唯一匹配的“序列等级＋引号内序列名”、途径全名、国家和组织全名、含间隔号的人物全名及明确维护的常用简称；跳过时间线简记、现有链接、代码、标题及注释，同一页对途径、序列、国家和人物目标只加一次；已建组织词条的每处正文提及均可链接。重新运行不会重复添加。别名、常用短名、同名词和其他需要判断语境的词条仍在建议清单中，不能把匹配当作关系事实。

扫描器会检查正文中的列表文字；旧版本遗漏的列表候选在更新后会重新出现，因此候选数不能与旧版直接比较。

## 提交前自动检查

项目使用 `.githooks/pre-commit` 检查本次暂存的词条，识别无歧义的途径、带等级的序列、国家和组织全名、人物全名及明确维护的常用简称。首次配置或在新克隆中执行 `git config --local core.hooksPath .githooks`；配置后每次提交自动检查。项目首次安装依赖仍需运行 `npm install`。

发现缺链时，提交会停止并列出涉及的文件。运行 `npm run links:apply` 后检查修改，将要提交的结果重新暂存即可。脚本只读取暂存区内容进行检查，不自动修改暂存区；自动补链命令修改工作区中所有符合条件的词条。`npm run links:preview` 可先查看影响范围。自动匹配不能消除所有语义歧义，简称白名单和候选清单仍需要维护；时间线简记继续使用 `event_summary_links`。

人物信息栏按组织分类名称匹配已建组织页面；存在唯一匹配时直接链接，不存在或有歧义时保留普通文字，详情链接仍指向人物正文。
